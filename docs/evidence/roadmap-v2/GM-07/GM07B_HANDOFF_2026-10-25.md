## Confirmed product decisions and proposed technical defaults

Trí confirmed on 2026-10-25:

1. Host and every member have equal preference weight.
2. Group history stores names only after consent from all group members; personal history stores the caller and member count only.

The contract proposes a precise ordering for the equal-weight preferences, comparable budget fit, consent-authorized recent-history penalty and seeded tie-break. That precise formula remains visible for Trí's final review; no runtime may silently treat these soft preferences as eligibility filters. Meal eligibility requires source-backed matching evidence. Unknown price remains eligible and is never converted or averaged.

## Command guards

Lifecycle writes (`updateSettings`, `updatePreferences`, `start`, `cancel`, `leave`, `finalize`) use `expectedVersion`. Ballot and waiting writes use their own `requestId`, `round`, `poolVersion`, and caller receipt; they do not fail solely because another member submitted a ballot. Exact ID/body replays return the original ACK before mutable state/version/quota checks. A different body under the same ID returns `REQUEST_ID_REUSED`.

`WAITING_1`/`WAITING_2` represents a shared timer. The member's private `ownWaiting` and each member's shared complete-ballot `submissionStatus` are distinct. A non-submitter may still send before the server deadline. A snapshot after expiry authenticates membership first and returns `410 ROOM_EXPIRED`; preview may return an `EXPIRED` minimal summary.
