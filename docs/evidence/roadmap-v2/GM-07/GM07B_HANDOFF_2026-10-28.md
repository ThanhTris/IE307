## Summary of 2026-10-28 closures

1. **NO_CONSENSUS Schema & Fixture Parity**:
   Fixed the schema smoke fixture so `NO_CONSENSUS` properly asserts `scoreVersion = null`, `rankingVersion = null`, `winner = null`, and `topDishes = []`, matching `dish-session-v4b.schema.json`.

2. **Semantic Result Validation**:
   Implemented `check_terminal_result_semantics` to verify rules beyond structural JSON Schema:
   - Tied scores share identical dense rank (e.g. `8, 8, 7` maps to ranks `1, 1, 2`).
   - Ranks strictly increment by 1 when score decreases (no rank gaps).
   - Winner dish must have the highest score in `topDishes` and rank 1.
   - DECIDED results require non-null R1 `scoreVersion` and `rankingVersion`.
   - NO_CONSENSUS results must have empty podium and null versions.

3. **`updateSettings` Authority and `poolVersion` Stability**:
   - Explicitly documented and tested that only the room host may invoke `updateSettings`; non-host callers receive error code `NOT_HOST`.
   - Submitting identical settings or updating only `desiredAt` increments room `version` but performs a no-op on the pool, leaving `poolVersion` and candidate dishes unchanged.
   - Only changes that alter the pool size (`dishCount`) or meal criteria regenerate the candidate pool and increment `poolVersion`.

4. **History & Result Projections**:
   - Verified `historyPage` DTO schema validation for both personal and group scoped records.
   - Preserves immutable podium projection across retry, history view, and notification routing.
