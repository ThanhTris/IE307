# GM-03 isolated QA Bruno collection

Select the private `Local.<run-id>.private.bru` environment generated by `npm run qa:start -- --run-id <id> --api-port 54371 --db-port 54372`. It contains only the loopback URL, public anon key and run ID; it is gitignored and removed by `qa:stop`.

Run the collection in order: GoTrue health → guest signup → refresh → authenticated REST identity → missing JWT → forged JWT. Signup creates an anonymous identity inside this disposable database. `qa:stop` tears down the owned Supabase project and database volume, so all test identities are removed with that QA run. Never select a Bruno environment pointing at the application database.

The checked-in example environment contains placeholders only. The automated equivalent is `npm run qa:test -- --run-id <id>`; it records sanitized output under `.work/qa/<id>/` and never writes credentials or guest IDs to reports. Signup and refresh response panes contain short-lived credentials; do not capture or publish those response bodies. Use the Runner assertions to show outcomes.
